Cloudflare Worker Deployment

CORS proxy for FRED & BLS APIs — deploy in 10 minutes, free forever

What This Does & Why You Need It

FRED and BLS don't return Access-Control-Allow-Origin headers, which means browsers block JavaScript from calling them directly. This is called CORS (Cross-Origin Resource Sharing).

Locally, server.py handles this by proxying API calls through Python. But on GitHub Pages, there's no server — it's static HTML only. A Cloudflare Worker solves this: it's a tiny script that runs on Cloudflare's edge network, receives your API call, forwards it to FRED/BLS, and returns the response with proper CORS headers. Free tier gives you 100,000 requests per day.

BEA does not need this. BEA already supports CORS, so the dashboard calls it directly. This Worker is only for FRED and BLS.

The Complete Worker Code

This single script handles both FRED (GET requests) and BLS (POST requests). Copy the entire block:

export default {
  async fetch(request) {
    // Handle CORS preflight
    if (request.method === 'OPTIONS') {
      return new Response(null, {
        headers: {
          'Access-Control-Allow-Origin': '*',
          'Access-Control-Allow-Methods': 'GET, POST, OPTIONS',
          'Access-Control-Allow-Headers': 'Content-Type',
        }
      });
    }

    const url = new URL(request.url);
    const params = url.search; // everything after the ?
    let targetUrl;
    let fetchOptions = {};

    if (request.method === 'POST') {
      // ── BLS: POST requests ──
      targetUrl = 'https://api.bls.gov/publicAPI/v2/timeseries/data/';
      const body = await request.text();
      fetchOptions = {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: body,
      };
    } else {
      // ── FRED: GET requests with query params ──
      targetUrl = 'https://api.stlouisfed.org/fred/series/observations' + params;
      fetchOptions = { method: 'GET' };
    }

    try {
      const resp = await fetch(targetUrl, fetchOptions);
      const data = await resp.text();

      return new Response(data, {
        status: resp.status,
        headers: {
          'Content-Type': 'application/json',
          'Access-Control-Allow-Origin': '*',
          'Cache-Control': 'public, max-age=300',
        }
      });
    } catch (err) {
      return new Response(JSON.stringify({ error: err.message }), {
        status: 502,
        headers: {
          'Content-Type': 'application/json',
          'Access-Control-Allow-Origin': '*',
        }
      });
    }
  }
};

What Each Section Does

  • OPTIONS handler (lines 3-11): Browsers send a "preflight" OPTIONS request before the real one. This tells the browser "yes, I accept requests from any origin."
  • POST branch (lines 17-24): If the dashboard sends a POST (used for BLS), forward it to the BLS API with the JSON body intact.
  • GET branch (lines 26-29): If the dashboard sends a GET (used for FRED), take all the query parameters (?series_id=CPIAUCSL&api_key=...&units=pc1) and forward them to FRED's endpoint.
  • Response (lines 32-40): Return whatever FRED/BLS sent back, but add Access-Control-Allow-Origin: * so the browser allows it. Also adds 5-minute caching to reduce redundant calls.
  • Error handling (lines 41-48): If the upstream API is down or unreachable, return a clean JSON error instead of crashing.

Step-by-Step Deployment

1 Create a Cloudflare Account

Go to dash.cloudflare.com/sign-up

  • Enter your email and a password
  • Verify your email (check inbox for confirmation link)
  • You do not need to add a domain or a website — skip any prompts about that
  • The free tier is all you need (100,000 Worker requests/day)
2 Go to Workers & Pages

Once logged in to the Cloudflare dashboard:

  • Look at the left sidebar
  • Click "Workers & Pages" (it has a wrench/gear icon)
  • If you don't see it, click the hamburger menu (☰) at the top-left to expand the sidebar
3 Create a New Worker

On the Workers & Pages screen:

  • Click the blue "Create" button
  • You'll see two tabs at the top: "Workers" and "Pages" — make sure "Workers" is selected
  • Click "Create Worker"
  • Cloudflare gives your worker a random name like cold-frost-a1b2 — change it to something recognizable:
    ghost-api-proxy
  • Click "Deploy" — don't worry about the code yet, we'll edit it next
4 Open the Code Editor

After deploying the default "Hello World" worker:

  • You'll land on the worker's overview page
  • Click "Edit Code" (blue button, top right) — this opens Cloudflare's online code editor
  • You'll see a file called worker.js in the left panel with some default code
5 Replace the Code

In the code editor:

  • Select all the existing code (Ctrl + A on Windows, Cmd + A on Mac)
  • Delete it (press Delete or Backspace)
  • Paste the Worker code from above (Ctrl + V / Cmd + V)
  • You can click the "Copy to Clipboard" button at the top of this page to copy it first
Make sure you replaced ALL the code. The editor should show the export default block and nothing else — no leftover addEventListener from the default template.
6 Deploy

Click the blue "Deploy" button in the top-right corner of the code editor.

  • Cloudflare compiles and deploys your Worker globally in about 2 seconds
  • You'll see a green success message
  • Your Worker is now live at:
    https://ghost-api-proxy.YOUR_SUBDOMAIN.workers.dev
7 Copy Your Worker URL

After deploying, look for the URL displayed on the page. It follows this pattern: 

https://ghost-api-proxy.YOUR_SUBDOMAIN.workers.dev

YOUR_SUBDOMAIN is the subdomain Cloudflare assigned to your account when you signed up. It's usually something like a1b2c3d4 or you may have chosen a custom one.

  • Click the URL to open it in a new tab — you should see {"error":"..."} or a blank response, which is fine. It means the Worker is running but no valid API params were passed.
  • Copy this URL — you'll paste it into the dashboard next
8 Connect Your Dashboard

Open your Economic Indicators Terminal (either locally or on GitHub Pages):

  • Click the "API" button in the top-right corner
  • Paste your FRED API key in the first field
  • Scroll down to "CORS Proxy URL"
  • Paste your Worker URL:
    https://ghost-api-proxy.YOUR_SUBDOMAIN.workers.dev
  • Click "Test All Keys" — you should see:
    FRED: Connected (via Cloudflare Worker) Latest CPI: 2026-02-01 = 2.80%
  • Click "Save & Connect"
That's it. Your dashboard now fetches live FRED data through your Cloudflare Worker, bypassing CORS. The Worker URL and API keys are stored in localStorage — they never appear in your code or Git repo.

Testing Your Worker Directly

You can test the Worker by pasting this URL into any browser tab (replace the subdomain and API key):

https://ghost-api-proxy.YOUR_SUBDOMAIN.workers.dev?series_id=CPIAUCSL&api_key=YOUR_FRED_KEY&file_type=json&observation_start=2025-01-01&units=pc1&frequency=m&sort_order=desc&limit=3

If everything is working, you'll see raw JSON with CPI observations. If you see an error, double-check:

  • The Worker URL is exactly right (no trailing slash needed)
  • Your FRED API key is valid
  • The Worker code was fully replaced (no leftover default code)

How the Dashboard Uses the Proxy

When the dashboard detects it's running on a remote host (not localhost), it routes FRED calls through your Worker URL instead of calling FRED directly:

// Without proxy (blocked by CORS):
https://api.stlouisfed.org/fred/series/observations?series_id=CPIAUCSL&...

// With proxy (CORS headers added by Worker):
https://ghost-api-proxy.YOUR_SUBDOMAIN.workers.dev?series_id=CPIAUCSL&...

The Worker receives the exact same query parameters, forwards them to FRED, gets the response, adds the Access-Control-Allow-Origin: * header, and returns it. The dashboard doesn't know the difference — it gets the same JSON either way.

Security Considerations

Your FRED API key is visible in the Worker request URL. This is the same as any browser-based API call — the key travels in the query string. For FRED and BLS (free government APIs with no billing), this is acceptable. If you later use this pattern with paid APIs, you'd store the key as a Cloudflare Worker Secret instead of passing it in the URL.

Troubleshooting

Worker returns "Hello World" instead of API data

You didn't replace the default code. Go back to Workers & Pages → click your worker → Edit Code → select all → delete → paste the code from this page → Deploy.

"Script startup exceeded CPU time limit"

The Worker code has a syntax error. Open the editor, check for missing brackets or semicolons. Use the browser console in the Cloudflare editor to see the exact error.

Dashboard still shows CORS errors

Check that the proxy URL in your dashboard settings matches exactly — no trailing slash, no extra spaces. Open browser DevTools (F12) → Network tab → find the failed request → verify the URL starts with your Worker domain, not api.stlouisfed.org.

"502 Bad Gateway" from the Worker

The upstream API (FRED or BLS) is temporarily down or unreachable. Wait a few minutes and try again. The Worker's error handler returns a clean JSON message in this case.
